# 我的设计准则与偏好

这些准则来自用户在多个项目、多轮迭代中的明确反馈。做界面、交互、动效和文案时默认遵循；与用户的新指令冲突时，以新指令为准。

标记说明：**【明确要求】**是用户亲口提过的；**【默认做法】**是目前采用、用户没有反对的选择，可以在有更好理由时调整，但要说明。

## 核心原则

1. **主界面只突出核心区域**【明确要求】。每个页面只保留“最重要的一件事”，其余设置、选择、编辑都收进从顶部按钮弹出的面板或弹层。
2. **一屏看完，尽量不滚动**【明确要求】。整页不滚动；确实很长的列表可以在自己的区域内滚动，滚动条自动隐藏或不显示。
3. **不要底部导航**【明确要求】。只用左上角一个图标返回首页，顶栏保持纤薄，只放标题、少量操作和设置。
4. **零重叠，关键信息字要大**【明确要求】。元素互相遮挡、图片压住按钮、3D 对象互相重叠都是缺陷。结果、倒计时、标题等关键信息用大字号。
5. **输入越少越好**【明确要求】。添加流程只要求最关键的字段（例如图片加名称），其他放进“更多信息（选填）”，以后可以补。
6. **选择用点击和下拉，不用横向拖动**【明确要求】。类别用下拉选择，选中后立刻展示并可编辑的选项；可以新增类别和选项，新增的必须自动保存。
7. **所有页面统一处理，不只修一个**【明确要求】。像“PWA 全屏适配”这类问题，要在每个工具里一起解决。
8. **接入系统能力**【明确要求】。能用系统通知、分享、安装的地方就接入，并在做不到时诚实说明限制。
9. **切换要快**【明确要求】。倾向单页应用，页面之间切换不能有明显延迟或整页刷新。
10. **动效要自然、逼真**【明确要求】。优先用物理模拟，而不是生硬的缓动曲线；3D 区域尽量大；动作之间不能穿帮。
11. **语气友好、有趣**【明确要求】。例如倒计时用搞笑风格，到点后有语音，没人理还会换着花样越来越急。界面文字与说明用中文。
12. **默认值贴近真实生活**【明确要求】。例如“轮到谁”的默认选项是宝宝、爸爸、妈妈，并带 emoji。
13. **名字和图标要亲切、好记**【明确要求】。例如把产品名定为“趣日常”，图标用微笑的太阳。用户把“怎样更合适”交给设计者判断，所以给出选择时要附上理由。

## 视觉风格【默认做法】

- 背景用暖纸色，卡片用柔和的淡彩色底，主色用珊瑚色，辅色用紫色，少用重阴影。
- 圆角偏大（卡片 24 到 30px，按钮胶囊形），图标优先用 emoji 或简洁的描边图标。
- 字号参考：关键信息不小于 24px，辅助说明不小于 12 到 13px，触控目标不小于 40px。
- 弹层：手机用底部弹层，电脑用居中卡片；标题栏吸顶，关闭按钮始终可点。
- 同时提供浅色与深色模式，用 CSS 变量统一管理颜色，并跟随系统。
- 首页用 2×2 的大磁贴，每个磁贴有一个大 emoji、标题和一行说明；运行中的状态（如倒计时）用小角标提示。

## 评审清单

交付任何界面前逐项检查，并用截图验证（不要只凭代码判断）：

- [ ] 在 360×640、390×844 和桌面宽度下都截过图。
- [ ] 页面没有整页滚动，没有横向溢出，没有多余的顶部空白。
- [ ] 没有底部导航，返回方式只有一个。
- [ ] 没有任何元素重叠或被遮挡，关键信息够大。
- [ ] 添加流程只需要最关键的字段。
- [ ] 弹层内容在手机上完整可见，必要时在弹层内滚动。
- [ ] 深色模式下可读，安全区（刘海、底部横条）没有被遮挡。
- [ ] 文案是中文，语气友好，没有技术术语。

## 避免

- 底部导航、可见的滚动条、页面顶部的大块留白。
- 把所有设置都堆在主界面。
- 靠左右拖动才能选类别。
- 要求用户一次填写很多字段。
- 在用户只要求“给建议”时直接动手实现。
